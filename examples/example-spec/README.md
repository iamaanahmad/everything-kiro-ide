# Example Spec: Password Reset

A minimal, complete example of the real Kiro spec file layout: `.kiro/specs/password-reset/{requirements,design,tasks}.md`.

Copy the `.kiro/specs/` directory into your own workspace to see the format in place, or use it as a reference when writing your own spec by hand. In normal use you wouldn't write these by hand — you'd describe the feature to Kiro and it drafts `requirements.md` first, waits for your approval, then `design.md`, then `tasks.md`. This example shows what that conversation produces.

See [`skills/development-workflows/spec-driven-development.md`](../../skills/development-workflows/spec-driven-development.md) for the full workflow explanation, including the EARS acceptance-criteria format and the approval gates between phases.
